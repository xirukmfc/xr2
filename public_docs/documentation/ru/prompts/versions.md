# Версии и развертывание

xR2 использует Git-подобную систему версионирования, которая позволяет безопасно итерировать над промптами, сохраняя стабильную продакшен-версию.

## Жизненный цикл версии

Каждая версия проходит через следующие статусы:

```
Draft → Production → Inactive
```

| Статус | Значение | Доступ через API |
|--------|---------|------------|
| **Draft** | В разработке | Недоступен |
| **Production** | Активен в продакшене | Ответ по умолчанию |
| **Inactive** | Приостановлен | Через параметр `status: "inactive"` |

## Создание версий

### Скопировать текущую версию

1. Перейдите в **Version History** в левой панели
2. Нажмите **New version**
3. Выбирете **Start from scratch**
4. Создается новый черновик с пустым содержимым

### Из существующей версии

1. Перейдите в **Version History** в левой панели
2. Найдите версию, которую хотите скопировать и перейдите в нее
3. Нажмите **New version**
4. Выбирете **Copy current version**
5. Создается новый черновик с тем же содержимым


## Номера версий

Версии нумеруются последовательно:

- v1, v2, v3...

Номер назначается автоматически и не может быть изменен.

## Развертывание в продакшен

### Развертывание версии

1. Выберите версию в Version History
2. Нажмите **Publish**

**Что происходит:**

- Статус выбранной версии → **Production**
- Предыдущая продакшен-версия → **Inactive**
- API теперь возвращает новую версию по умолчанию

### Развертывание одним кликом

На панели инструментов редактора нажмите **Deploy**, чтобы мгновенно развернуть текущую просматриваемую версию.

> ⚠️ **Предупреждение:** Развертывание происходит немедленно. Промежуточной среды нет — версия становится активной сразу после нажатия Deploy.

## Откат

Допустили ошибку? Откатитесь за секунды:

1. Перейдите в **Version History**
2. Найдите предыдущую рабочую версию
3. Нажмите **Publish**

Старая версия снова активна.

## Детали версии

Каждая версия отслеживает:

| Поле | Описание |
|-------|-------------|
| **Version Number** | Последовательный идентификатор (v1, v2...) |
| **Status** | Текущая стадия жизненного цикла |
| **Created At** | Когда версия была создана |
| **Created By** | Кто создал |
| **Deployed At** | Когда была развернута (если применимо) |
| **Deployed By** | Кто развернул |
| **Changelog** | Автоматически сгенерированная сводка изменений |

## Журнал изменений

xR2 отслеживает изменения при обновлении версий. Поле changelog хранит информацию об изменениях:

- Переходы статусов (draft → testing → production)
- Обновления конфигурации переменных
- Изменения конфигурации модели
- Модификации содержимого промптов (system, user, assistant)


## Метрики производительности по версиям

Отслеживайте производительность каждой версии:

| Метрика          | Описание                             |
|------------------|--------------------------------------|
| **Requests**     | Всего API-вызовов                    |
| **Source name**  | Откуда чаще всего запрашивали версию |
| **Avg Latency**  | Время ответа в мс                    |
| **Avg Tokens**   | Токенов на запрос                    |
| **Success Rate** | % успешных вызовов                   |
| **Conversions**  | Количество связанных событий         |

Используйте эти данные для сравнения эффективности версий.

## Лучшие практики

### 1. Создавайте версию перед большими изменениями

Всегда создавайте новую версию перед:

- Капитальными переработками промптов
- Добавлением/удалением переменных
- Изменением конфигурации модели

### 2. Используйте статус Draft или A/B Testing

1. Вы можете при запросе промпта указывать номер версии, которую хотите получить. Тогда вам не нужно будет ее публиковать. Так вы сможете делать точечные тесты
2. Так же вы можете добавить новую версию и запустить A/B Testing с версией в продакшн и новой версией в статусе Draft. В этом случаке все запросы будут по умолчанию разделяться 50/50 на 2 версии и вы по итогам сможете замерить эффективность и выбрать лучшую.

Тестируйте с параметром `status: "draft"` в API-вызовах.

### 3. Документируйте изменения

Добавляйте описательные примечания при создании версий:

- "Added multilingual support"
- "Fixed tone issue with angry customers"
- "Optimized for GPT-4 Turbo"

### 4. Сохраняйте стабильность продакшена

Избегайте развертывания в часы пик. Планируйте развертывание на время с низким трафиком.

### 5. Мониторьте после развертывания

Проверяйте аналитику в течение 15-30 минут после развертывания:

- Скачок частоты ошибок?
- Увеличение задержки?
- Падение конверсии?

Откатите, если метрики ухудшаются.

## Выбор версии через API

По умолчанию API возвращает версию **Production**. Переопределите параметрами:

```bash
# Get production version (default)
curl -X POST .../get-prompt -d '{"slug": "support", "source_name": "app"}'

# Get specific version
curl -X POST .../get-prompt -d '{"slug": "support", "source_name": "app", "version_number": 2}'

# Get testing version
curl -X POST .../get-prompt -d '{"slug": "support", "source_name": "app", "status": "testing"}'
```
