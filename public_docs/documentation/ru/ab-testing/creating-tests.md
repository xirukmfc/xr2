# Создание A/B-тестов

Узнайте, как настроить и запустить A/B-тесты в xR2.

## Предварительные требования

Перед созданием теста вам понадобится:

1. **Промпт** с минимум двумя версиями
2. **Настроенное отслеживание событий** для вашей метрики успеха
3. **Трафик** — достаточно пользователей для достижения статистической значимости

## Пошаговое руководство

### Шаг 1: Подготовьте версии

Создайте две версии вашего промпта:

**Версия A (Контроль)**
- Обычно ваша текущая продакшен-версия
- Базовая линия, с которой вы сравниваете

**Версия B (Тестовая)**
- Новая версия, которую вы хотите протестировать
- Содержит ваше гипотетическое изменение

### Шаг 2: Создайте тест

1. Перейдите в **Аналитика** → **A/B-тесты**
2. Нажмите **+ Новый A/B-тест**
3. Заполните конфигурацию:

| Поле | Описание                                                   |
|------|------------------------------------------------------------|
| **Название теста** | Описательное название (например, «Эксперимент с тоном Q1») |
| **Промпт** | Выберите промпт для тестирования                           |
| **Версия A** | Выберите контрольную версию                                |
| **Версия B** | Выберите тестовую версию                                   |
| **Лимит запросов** | Общее количество запросов до завершения теста              |
| **Событие успеха** | Воронка для сравнения результатов                         |

4. Нажмите **Создать тест**

### Шаг 3: Проверьте и запустите

Перед запуском проверьте:
- Правильные версии выбраны?
- Событие успеха отслеживается корректно?
- Лимит запросов достаточен для значимости?

Нажмите **Запустить тест**, чтобы начать распределение трафика.

## Параметры конфигурации

### Лимит запросов

Сколько запросов до автоматического завершения теста:

| Лимит запросов | Сценарий использования |
|----------------|------------------------|
| 1 000 | Быстрый ориентировочный тест |
| 5 000 | Стандартный тест |
| 10 000+ | Результат с высокой достоверностью |

Меньшие лимиты означают более быстрые результаты, но меньшую уверенность. См. [Статистическая значимость](statistics.md) для рекомендаций.

### Распределение трафика

В настоящее время xR2 использует фиксированное распределение 50/50:
- 50% запросов получают версию A
- 50% запросов получают версию B

Распределение рандомизировано для каждого запроса.

## Управление запущенными тестами

### Просмотр статуса

Перейдите в **A/B-тесты**, чтобы увидеть:
- Текущее количество запросов
- Показатели конверсии по вариантам
- Время работы
- Прогнозируемое завершение

### Пауза/Возобновление

В настоящее время не поддерживается. Тесты работают до завершения или отмены.

### Отмена теста

Если нужно остановить досрочно:
1. Найдите тест в списке
2. Нажмите **Отменить**
3. Подтвердите отмену

Отменённые тесты имеют неполные данные. Результаты могут быть статистически незначимыми.

## Завершение теста

Тест завершается автоматически, когда:
- Достигнут лимит запросов
- Вы завершили его вручную

После завершения:
- Трафик возвращается только на продакшен-версию
- Результаты доступны для анализа
- Победителя можно развернуть

## Пример: Создание теста тона

**Гипотеза**: Более дружелюбный тон увеличит количество регистраций.

### 1. Создание версий

**Версия 3 (Контроль)**:
```
System: You are a professional customer service agent.
Respond formally and efficiently.
```

**Версия 4 (Тестовая)**:
```
System: You are a friendly helper who loves assisting customers!
Be warm, use casual language, and add encouraging words.
```

### 2. Создание теста

- **Название теста**: «Тест дружелюбного тона»
- **Промпт**: `onboarding-assistant`
- **Версия A**: Версия 3
- **Версия B**: Версия 4
- **Лимит запросов**: 5 000
- **Событие успеха**: `signup_completed`

### 3. Мониторинг

Проверяйте панель A/B-тестов ежедневно:
- День 1: A=2,1%, B=2,8% (слишком рано)
- День 3: A=2,3%, B=3,1% (многообещающе)
- День 7: A=2,4%, B=3,2% (значимо!)

### 4. Заключение

Версия B побеждает с улучшением показателя регистрации на 33%. Разверните Версию 4 в продакшен.

## Несколько тестов

### Последовательные тесты

Проводите один тест за раз для каждого промпта:
1. Тест A vs B → B побеждает
2. Тест B vs C → C побеждает
3. Разверните C

### Параллельные тесты (разные промпты)

Вы можете проводить тесты на разных промптах одновременно:
- `onboarding` — Тестирование тона
- `checkout` — Тестирование длины

### Избежание конфликтов

Не проводите несколько тестов на одном промпте. Результаты будут искажены.

## Лучшие практики

### 1. Документируйте всё

Создайте журнал тестов:
```
Test: Friendly Tone Test
Date: 2025-01-15
Hypothesis: Friendly tone increases signups
Versions: v3 (control) vs v4 (treatment)
Metric: signup_completed
Result: TBD
```

### 2. Уведомите команду

Перед началом:
- Сообщите разработчикам (код может вести себя по-разному)
- Сообщите поддержке (пользовательский опыт может различаться)
- Сообщите заинтересованным сторонам (метрики могут колебаться)

### 3. Избегайте подглядывания

Не принимайте решения на основе ранних результатов:
- Результаты 1-го дня ненадёжны
- Дождитесь статистической значимости
- Доверяйте процессу

### 4. Планируйте следующий тест

Пока один тест запущен, готовьте следующий:
- Анализируйте текущие выводы
- Формируйте новые гипотезы
- Создавайте новые версии

## Устранение неполадок

### Тест не получает трафик

- Вызывается ли промпт через API?
- Проверьте соответствие slug
- Убедитесь, что статус теста — «Running»

### События не связываются

- Убедитесь, что `trace_id` передаётся в отслеживание событий
- Проверьте, что название события соответствует событию успеха
- Проверьте события во вкладке «Недавние события»

### У одного варианта нет данных

- Тест может быть слишком новым
- Проверьте, возвращает ли API оба варианта
- Убедитесь, что трафик действительно достигает промпта
