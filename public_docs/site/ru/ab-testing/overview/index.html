Обзор A/B-тестирования

A/B-тестирование позволяет сравнивать разные версии промптов на реальных пользователях и выбирать победителя на основе данных, а не догадок.

Зачем проводить A/B-тесты промптов?

Разработка промптов часто идёт методом проб и ошибок: - «Лучше ли эта формулировка?» - «Стоит ли добавить больше контекста?» - «Пользователи предпочтут формальный или неформальный тон?»

A/B-тестирование даёт однозначные ответы на эти вопросы, показывая каждую версию реальным пользователям и измеряя результаты.

Как это работает

1. Создайте две версии промпта (A и B)
2. Запустите A/B-тест
3. xR2 распределяет трафик 50/50
4. Отслеживайте события конверсии
5. Анализируйте, какая версия побеждает
6. Разверните победителя

Распределение трафика

Когда тест запущен, API автоматически возвращает: - Версию A для ~50% запросов - Версию B для ~50% запросов

Распределение случайное, но постоянное для каждого запроса.

Ответ с информацией об A/B-тесте

{
  "slug": "onboarding",
  "system_prompt": "...",
  "trace_id": "evt_xxx",
  "ab_test_id": "test_123",
  "ab_test_name": "Tone Experiment",
  "ab_test_variant": "A"
}

Ваш код менять не нужно — xR2 сам управляет распределением.

Ключевые понятия

Вариант

Конкретная версия промпта в тесте: - Вариант A (Контроль): Обычно текущая продакшен-версия - Вариант B (Тестовый): Новая версия, которую вы тестируете

Событие конверсии

Действие, которое вы измеряете: - signup_completed - purchase_completed - positive_feedback

Размер выборки

Количество пользователей, которые увидели каждый вариант. Больше выборка = надёжнее результаты.

Статистическая значимость

Уверенность в том, что разница не случайна. xR2 рассчитывает это автоматически.

Что можно тестировать?

Содержание промпта

Тест Пример
Тон Формальный vs. Неформальный
Длина Подробный vs. Краткий
Структура Маркированные списки vs. Абзацы
Инструкции Строгие vs. Гибкие

Вариации системного промпта

Version A: "You are a professional assistant."
Version B: "You are a friendly helper who uses casual language."

Шаблоны пользовательского промпта

Version A: "User question: {{question}}"
Version B: "The user {{user_name}} asks: {{question}}.
            Consider their history: {{context}}"

Включение переменных

Version A: Uses 3 variables
Version B: Uses 5 variables (more context)

Жизненный цикл теста

Draft → Running → Completed/Cancelled
Статус Значение
Draft Тест создан, но не запущен
Running Активно распределяет трафик
Completed Достигнут лимит запросов
Cancelled Остановлен вручную досрочно

Сценарии использования

Оптимизация конверсии

Цель: Увеличить процент регистраций

Тест: Сравнить два промпта онбординга - A: Текущий промпт (12% конверсия) - B: Новый промпт с большим энтузиазмом

Результат: B побеждает с 18% конверсией (+50% улучшение)

Качество поддержки

Цель: Уменьшить количество дополнительных вопросов

Тест: Сравнить стили ответов - A: Подробные объяснения - B: Краткие с пунктами действий

Результат: A снижает количество дополнительных вопросов на 25%

Влияние на выручку

Цель: Увеличить сумму покупки

Тест: Сравнить подходы к допродажам - A: Ненавязчивая рекомендация - B: Прямое сравнение с преимуществами

Результат: B увеличивает средний чек на $12

Лучшие практики

1. Тестируйте одну вещь за раз

Хорошо: Изменить только тон Плохо: Изменить тон, длину и структуру одновременно

Если вы меняете несколько вещей, вы не узнаете, что именно вызвало разницу.

2. Определите метрики успеха заранее

Перед началом: - Какое событие означает успех? - Какое улучшение значимо? - Сколько выборок вам нужно?

3. Проводите тесты достаточно долго

Не останавливайте тест раньше времени, потому что один вариант выглядит лучше. Дождитесь статистической значимости.

4. Документируйте свою гипотезу

Запишите, что вы ожидаете: - «Я считаю, что версия B будет конвертировать лучше, потому что...» - Это предотвращает рационализацию постфактум.
