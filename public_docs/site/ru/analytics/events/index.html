Отслеживание событий

События — основа аналитики xR2. Они позволяют отслеживать действия пользователей и связывать их с конкретными промптами.

Что такое событие?

Событие представляет что-то, что произошло:

  • Пользователь зарегистрировался
  • Покупка завершена
  • Контент сгенерирован
  • Тикет поддержки решён

Каждое событие связано с промптом через trace_id.

Структура события

{
  "trace_id": "evt_abc123_1234567890_xyz",
  "event_name": "purchase_completed",
  "source_name": "web_app",
  "user_id": "user_123",
  "session_id": "session_456",
  "value": 99.99,
  "currency": "USD",
  "metadata": {
    "order_id": "order_789",
    "product_id": "prod_abc"
  }
}

Обязательные поля

Поле Тип Описание
trace_id string Из ответа get-prompt
event_name string Идентификатор события (определяется в дашборде)
source_name string Откуда пришло событие

Необязательные поля

Поле Тип Описание
user_id string Уникальный идентификатор пользователя
session_id string Идентификатор сессии
value number Денежная стоимость
currency string Код валюты (USD, EUR и т.д.)
metadata object Пользовательские поля

Определение событий

Перед отслеживанием определите события в дашборде:

  1. Перейдите в Аналитика → Определения событий
  2. Нажмите + Новое событие
  3. Настройте:
    • Имя события: Уникальный идентификатор (например, purchase_completed)
    • Категория: Группировка (например, "Конверсия", "Вовлечённость")
    • Описание: Что представляет это событие
  4. Определите схему метаданных:
    • Обязательные поля (должны присутствовать)
    • Необязательные поля (могут быть включены)
    • Типы полей (string, number, boolean)
  5. Нажмите Сохранить

Пример определения события

Событие: purchase_completed

Name: purchase_completed
Category: Conversion
Description: User completed a purchase

Required Fields:
  - order_id (string): Unique order identifier

Optional Fields:
  - product_id (string): Product purchased
  - quantity (number): Number of items
  - discount_applied (boolean): Whether discount was used

Отправка событий

curl -X POST https://xr2.uk/api/v1/events \
  -H "Authorization: Bearer xr2_prod_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_id": "evt_abc123_1234567890_xyz",
    "event_name": "purchase_completed",
    "source_name": "web_app",
    "user_id": "user_123",
    "value": 99.99,
    "currency": "USD",
    "metadata": {
      "order_id": "order_789"
    }
  }'

Ответ на событие

{
  "status": "success",
  "event_id": "evt_unique_id",
  "trace_id": "evt_abc123_1234567890_xyz",
  "event_name": "purchase_completed",
  "timestamp": "2025-01-15T10:30:00Z",
  "is_duplicate": false
}

Дедупликация

События дедуплицируются по trace_id + event_name. Повторная отправка того же события возвращает:

{
  "status": "success",
  "is_duplicate": true
}

Это предотвращает двойной подсчёт.

Типичные паттерны событий

Воронка регистрации

1. signup_started     — Пользователь нажал "Регистрация"
2. email_entered      — Email отправлен
3. password_created   — Пароль установлен
4. signup_completed   — Аккаунт создан

Воронка покупки

1. product_viewed     — Пользователь просмотрел страницу товара
2. added_to_cart      — Товар добавлен в корзину
3. checkout_started   — Начат процесс оформления
4. payment_entered    — Платёжные данные введены
5. purchase_completed — Заказ подтверждён

Поток поддержки

1. support_requested  — Пользователь запросил помощь
2. ai_response_sent   — AI предоставил ответ
3. feedback_given     — Пользователь оценил ответ
4. issue_resolved     — Тикет закрыт

Отслеживание выручки

Отслеживайте денежную стоимость с помощью value и currency:

{
  "trace_id": "evt_xxx",
  "event_name": "purchase_completed",
  "source_name": "web_app",
  "value": 149.99,
  "currency": "USD",
  "metadata": {
    "order_id": "order_123",
    "items_count": 3
  }
}

xR2 агрегирует выручку по:

  • Промпту
  • Версии
  • Периоду времени
  • Варианту A/B-теста

Просмотр событий

Вкладка "Последние события"

Просматривайте события в реальном времени:

  • Название события и временная метка
  • Идентификаторы пользователя и сессии
  • Связанный промпт и версия
  • Детали метаданных

Фильтрация

Фильтруйте события по:

  • Названию события
  • Диапазону дат
  • Слагу промпта
  • ID пользователя
  • Диапазону значений

Лучшие практики

1. Определите события до написания кода

Спланируйте схему событий заранее:

  • Какие действия важны?
  • Какие данные собирать?
  • Как вы будете их анализировать?

2. Используйте единообразные названия

Следуйте соглашению:

  • Формат noun_verb: purchase_completed, signup_started
  • Строчные буквы с подчёркиваниями
  • Будьте конкретны: blog_post_shared, а не shared

3. Включайте контекст

Добавляйте релевантные метаданные:

Хорошо: 

{
  "event_name": "purchase_completed",
  "value": 99.99,
  "metadata": {
    "order_id": "123",
    "payment_method": "credit_card",
    "items_count": 2
  }
}

Плохо: 

{
  "event_name": "purchase"
}

4. Отслеживайте правильный момент

Отслеживайте, когда действие подтверждено, а не когда оно инициировано:

  • purchase_completed после успешного платежа
  • purchase_completed при нажатии "Оплатить"

5. Обрабатывайте ошибки

Если отслеживание события не удалось, не блокируйте пользовательский процесс:

try:
    client.track_event(...)
except Exception as e:
    logger.error(f"Event tracking failed: {e}")
    # Continue with user flow

Устранение неполадок

Событие не появляется

  1. Проверьте, что trace_id валиден (из недавнего запроса промпта)
  2. Убедитесь, что event_name соответствует определённому событию
  3. Проверьте, что метаданные соответствуют схеме
  4. Убедитесь, что API-ключ имеет права на отслеживание

Дублирующиеся события

  • Ожидаемое поведение: одинаковые trace_id + event_name = дедупликация
  • Проверьте, что ваш код не отправляет одно и то же событие несколько раз

Отсутствующие метаданные

  • Убедитесь, что обязательные поля присутствуют
  • Проверьте, что типы полей соответствуют схеме
