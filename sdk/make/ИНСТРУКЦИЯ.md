Перейдите на https://eu2.make.com/apps → Create new app

- **Base** <- `base.json`
- **Connections** <- `connections/xr2_api_key.json`

1. Connection test с реальным API key
2. Создайте scenario с модулем Get Prompt

## Основные компоненты Make.com приложения

### Base
Базовая конфигурация для всех модулей:
- `baseUrl` - API endpoint
- `headers` - заголовки по умолчанию
- `log.sanitize` - что скрывать в логах
- `response.error` - обработка ошибок

### Connection
Авторизация пользователя:
- `type: "apikey"` - тип авторизации
- `parameters` - какие данные запросить у пользователя (API key)
- `common.headers` - как использовать эти данные в запросах
- `test` - проверка валидности подключения

### Module
Функциональный модуль (действие):
- `parameters` - входные поля (mappable parameters)
- `interface` - выходные поля (что вернет модуль)
- `communication` - настройка API запроса/ответа
- `samples` - примеры для тестирования

## Как работает Make.com Custom App

```
┌─────────────────────────────────────────────────────────┐
│                    Make.com Platform                     │
│                                                           │
│  ┌────────────┐    ┌─────────────┐    ┌──────────────┐ │
│  │  Scenario  │───▶│  xR2 Module │───▶│ Next Module  │ │
│  └────────────┘    └─────────────┘    └──────────────┘ │
│                           │                              │
│                           │ uses                         │
│                           ▼                              │
│                    ┌─────────────┐                      │
│                    │ Connection  │                      │
│                    │ (API Key)   │                      │
│                    └─────────────┘                      │
│                           │                              │
│                           │ adds headers                 │
│                           ▼                              │
│                    ┌─────────────┐                      │
│                    │    Base     │                      │
│                    │ (baseUrl,   │                      │
│                    │  headers)   │                      │
│                    └─────────────┘                      │
│                           │                              │
└───────────────────────────┼──────────────────────────────┘
                            │
                            ▼ HTTP Request
                    ┌─────────────┐
                    │  xR2 API    │
                    │ xr2.uk/api  │
                    └─────────────┘
```

**Порядок применения:**
1. Base задает baseUrl и общие headers
2. Connection добавляет Authorization header
3. Module формирует конкретный запрос (url, method, body)
4. Make отправляет объединенный запрос к API
5. Response парсится согласно Interface
6. Данные передаются в следующий модуль сценария

## IML (Integromat Markup Language)

Язык для работы с данными в Make:

```
{{parameters.slug}}                    - значение параметра
{{body.trace_id}}                      - значение из ответа API
{{connection.apiKey}}                  - данные из connection
{{if(condition, true_val, false_val)}} - условие
{{ifempty(value, default)}}            - значение или дефолт
```

**Примеры использования:**

```json
// В Connection - подстановка API key:
"Authorization": "Bearer {{parameters.apiKey}}"

// В Module body - отправка параметра:
"slug": "{{parameters.slug}}"

// Опциональный параметр (отправить только если есть):
"version_number": "{{if(parameters.version_number, parameters.version_number)}}"

// Дефолтное значение:
"fields": "{{ifempty(parameters.fields, emptyobject)}}"
```

---

## Типы данных

| Type | Когда использовать | Пример |
|------|-------------------|--------|
| `text` | Обычная строка | API key, slug, название |
| `integer` | Целое число | version_number |
| `number` | Число с дробной частью | amount: 99.99 |
| `boolean` | true/false | success, is_active |
| `date` | Дата/время | created_at, deployed_at |
| `select` | Выбор из списка | status: [production, testing] |
| `array` | Список элементов | variables: [{name, type}] |
| `collection` | Группа полей (объект) | fields: {amount, currency} |

### Array - список одинаковых элементов

```json
{
    "name": "variables",
    "type": "array",
    "spec": [
        {"name": "name", "type": "text"},
        {"name": "type", "type": "text"}
    ]
}
```

Пользователь увидит список, каждый элемент содержит `name` и `type`.

### Collection - объект с фиксированными полями

```json
{
    "name": "fields",
    "type": "collection",
    "spec": [
        {"name": "amount", "type": "number"},
        {"name": "currency", "type": "text"}
    ]
}
```

Пользователь увидит группу полей для ввода amount и currency.

### Динамическая структура

Если API возвращает непредсказуемую структуру:

```json
{"name": "metadata", "type": "collection", "spec": []}
```

Пустой `spec: []` = пользователь сможет работать с любыми полями, которые вернет API.

## Тестирование

### 1. Connection Test

```bash
# Make автоматически выполняет:
GET https://xr2.uk/api/v1/check-api-key
Headers: {
    "Authorization": "Bearer xr2_prod_YOUR_KEY"
}

# Успех если:
# - Получен ответ: {"ok": true, "user": "username"}
```

### 2. Локальное тестирование через curl

```bash
# Check API Key
curl https://xr2.uk/api/v1/check-api-key \
  -H "Authorization: Bearer xr2_prod_YOUR_KEY"

# Get Prompt
curl -X POST https://xr2.uk/api/v1/get-prompt \
  -H "Authorization: Bearer xr2_prod_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"slug": "your-slug", "source_name": "make_sdk"}'

# Track Event
curl -X POST https://xr2.uk/api/v1/events \
  -H "Authorization: Bearer xr2_prod_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_id": "evt_xxx",
    "event_name": "test",
    "source_name": "make_sdk",
    "user_id": "user_123",
    "value": 99.99,
    "currency": "USD",
    "metadata": {
      "plan": "pro"
    }
  }'
```

### 3. Тестирование в Make.com Scenario

1. Создайте новый сценарий
2. Добавьте модуль xR2 → Get Prompt
3. Настройте connection с реальным API key
4. Введите slug существующего промпта
5. Run once
6. Проверьте output - все поля из interface должны быть доступны

## Частые ошибки

### ❌ "Invalid API key"
```
Причина: Неправильный Authorization header
Решение: Проверьте в Connection → common.headers:
  "Authorization": "Bearer {{parameters.apiKey}}"
```

### ❌ Модуль отправляет данные не как JSON
```
Причина: Не указан type в body
Решение: В communication.body:
  {
      "type": "json",
      "slug": "{{parameters.slug}}"
  }
```

### ❌ Optional параметры отправляются как null
```
Причина: Используется undefined или не используется условие
Решение: Используйте IML:
  "version_number": "{{if(parameters.version_number, parameters.version_number)}}"
```

### ❌ Interface не показывает вложенные поля
```
Причина: Не указан spec для array/collection
Решение: Определите структуру:
  {
      "name": "variables",
      "type": "array",
      "spec": [
          {"name": "name", "type": "text"}
      ]
  }
```

### ❌ Connection test не проходит
```
Причина: Неверный API ключ
Решение: Проверьте API key на https://xr2.uk/api-keys
  Connection test использует GET /check-api-key для проверки валидности ключа
```
